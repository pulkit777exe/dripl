# Excalidraw feature and architecture baseline

**Research cutoff:** 2026-09-24  
**Scope:** the public Excalidraw editor, the `@excalidraw/excalidraw` React package, the `excalidraw.com` app, and the collaboration/rendering code in the official repository. Claims below are limited to first-party sources: the official repository at pinned commits, official documentation, official release notes, and first-party issue/PR pages. DeepWiki can be useful as a secondary navigation aid, but no grade or parity claim below relies on it in place of the pinned first-party sources.

## Executive summary

- **The stable OSS editor is already a broad whiteboard, not just a sketch toy.** The shipped editor supports an infinite pan/zoom canvas, the standard shape/line/text/image tools, bound and labeled arrows, frames, images, embeds, groups, alignment/distribution, z-order, locking, undo/redo, libraries, scene search, Mermaid conversion, editable chart paste, localization, and light/dark themes. The most compact official feature list and the `v0.18.0` highlights substantiate this baseline. ([README, `v0.18.1`/a2ec288, 2026-04-20](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/README.md#L55-L72); [package changelog, `v0.18.1`/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/CHANGELOG.md#L14-L42))
- **The npm editor and the hosted app are different products.** The package supplies the editor and host APIs; it explicitly does **not** ship collaboration. The `excalidraw.com` app adds PWA/offline behavior, browser-local autosave, live collaboration, E2EE, and shareable read-only links. ([official FAQ, `v0.18.1`/a2ec288, 2026-04-20](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/dev-docs/docs/@excalidraw/excalidraw/faq.mdx#L3-L5); [README, `v0.18.1`/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/README.md#L74-L84))
- **Collaboration is room-based, client-encrypted, and deterministic rather than CRDT-based.** The first-party app creates a room ID plus random key, keeps the key in the URL fragment, encrypts Socket.IO payloads with AES-GCM before transmission, merges element IDs, and resolves competing versions using `version` and `versionNonce`; fractional indices preserve ordering. ([app data model, `v0.18.1`/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/excalidraw-app/data/index.ts#L128-L160); [encryption, `v0.18.1`/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/data/encryption.ts#L4-L28); [reconciliation, `v0.18.1`/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/data/reconcile.ts#L19-L40))
- **The renderer is a DPR-aware 2D-canvas system with layered canvases and aggressive local caching.** Elements and Rough.js drawables are cached in `WeakMap`s, static and interactive content use separate canvases, and hot-path renders are reduced to animation frames. However, viewport culling still scans every non-deleted element, so pan/zoom work is O(N); an open first-party issue documents that this remains unresolved. ([stable renderer, `v0.18.1`/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/scene/Renderer.ts#L23-L64); [issue #10512, opened 2025-12-14, still open at cutoff](https://github.com/excalidraw/excalidraw/issues/10512))
- **Keyboard operation is extensive, but non-visual canvas operation is not a documented current capability.** Stable controls expose labels/keyboard semantics, dialogs manage focus, and the editor has extensive shortcuts. In contrast, the official accessibility discussion says screen-reader support is “limited mainly to the interface, not the canvas contents”; a proposed screen-reader scene layer and initial keyboard-only shape placement are still unmerged as of this cutoff. ([issue #5759, opened 2022-10-13, open](https://github.com/excalidraw/excalidraw/issues/5759); [PR #11661, opened 2026-07-14, open/unmerged](https://github.com/excalidraw/excalidraw/pull/11661); [PR #12128, opened 2026-09-19, open/unmerged](https://github.com/excalidraw/excalidraw/pull/12128))
- **Do not fold paid/enterprise behavior into the OSS baseline.** Free, Plus, and Enterprise have materially different persistence, permissions, presentation, comments, voice, AI, cloud-library, and PDF/PPTX capabilities. The official site still labels Enterprise “coming soon” at the cutoff. ([official feature comparison, accessed 2026-09-24](https://plus.excalidraw.com/excalidraw-plus-vs-excalidraw); [Teams/Enterprise page, accessed 2026-09-24](https://plus.excalidraw.com/excalidraw-for-teams))

## 3. User-visible whiteboard baseline

### 3.1 Stable editor and free hosted app

- **Canvas/navigation:** infinite 2D canvas; pan, wheel/trackpad navigation, zoom, zoom-to-fit, page navigation, grid, view mode, zen mode, dark mode, and customizable canvas background. The official package list explicitly covers infinite canvas, zoom/pan, and dark mode; stable source exposes view/zen/grid modes and viewport controls. ([README, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/README.md#L57-L72); [stable help dialog, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/components/HelpDialog.tsx#L247-L296))
- **Creation tools in v0.18.1:** selection, rectangle, diamond, ellipse, line, arrow, freedraw, text, image, eraser, hand/panning, frame, web embed, and laser pointer. Magic-frame is a host-provided AI plugin path, not a self-contained offline tool. ([stable tool union, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/types.ts#L122-L137); [stable extra-tools menu, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/components/Actions.tsx#L341-L410))
- **Element model:** rectangles, ellipses, diamonds, lines, arrows, freehand paths, text, images, frames, web embeds/iframes, and AI magic frames are serialized element types. Common elements carry geometry, styles, seed, version, version nonce, fractional index, deletion/group/frame/binding/lock/link state. ([stable element types, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/element/types.ts#L40-L80); [stable element union, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/element/types.ts#L175-L213))
- **Editing and diagram behavior:** bound text, wrapped containers, labeled and bound arrows (including elbow arrows), point editing, automatic bindings, image cropping/flip/scale, links, element-to-element links, object snapping, and keyboard-created/navigable flowcharts. These are among the 0.18.0 feature highlights and are represented in the stable element/key-handler source. ([0.18.0 highlights, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/CHANGELOG.md#L20-L42); [stable key handler, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/components/App.tsx#L4104-L4208))
- **Organization and reuse:** grouping/ungrouping, duplicate, align and distribute, z-order, lock/unlock, frames, editable element stats, scene text/frame-name search, command palette, and personal/public libraries. The stable package exposes library host APIs; durable hosted-library wiring is an app concern, not a bare-package guarantee. These are represented by stable actions and the 0.18.0 highlights for stats/search/command palette. ([stable command palette actions, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/components/CommandPalette/CommandPalette.tsx#L259-L383); [0.18.0 highlights](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/CHANGELOG.md#L20-L42))
- **Mermaid conversion:** the stable app exposes a Mermaid-to-Excalidraw dialog, previews the result, and inserts supported output as editor elements. Mermaid parsing is implemented by the separately published `@excalidraw/mermaid-to-excalidraw` package; the package API converts Mermaid syntax to element skeletons. Native conversion and image fallback differ by diagram type, so “Mermaid import” should not be read as universal editable conversion of every Mermaid grammar. ([stable Mermaid UI, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/components/TTDDialog/MermaidToExcalidraw.tsx#L24-L129); [official Mermaid API docs, stable tag](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/dev-docs/docs/@excalidraw/mermaid-to-excalidraw/api.mdx))
- **Spreadsheet-to-chart paste:** stable code recognizes one- or two-column numeric CSV/TSV/spreadsheet clipboard data and offers editable bar or line chart element groups. The later master source adds radar charts, but radar is not in v0.18.1. ([stable parser, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/charts.ts#L124-L164); [stable chart dialog, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/components/PasteChartDialog.tsx#L84-L133))
- **AI is host-extensible, not bundled into the editor contract.** The package exposes dialog/plugin components, but the first-party app supplies `onTextSubmit` and diagram-to-code calls to a configured AI backend. Free has limited AI; Plus advertises extended AI. ([stable TTD component contract, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/components/TTDDialog/TTDDialog.tsx#L58-L89); [host AI wiring, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/excalidraw-app/components/AI.tsx#L12-L156); [pricing, accessed 2026-09-24](https://plus.excalidraw.com/pricing))
- **Hosted-app behavior:** the first-party app is local-first, autosaves scene/app state to `localStorage`, stores binary files in IndexedDB, supports PWA installation/offline use, and can share E2EE read-only links. ([README, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/README.md#L74-L84); [LocalData, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/excalidraw-app/data/LocalData.ts#L1-L15); [PWA config, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/excalidraw-app/vite.config.mts))

## 4. Collaboration model

### 4.1 What the package guarantees—and does not

The React package exposes change/pointer callbacks and an imperative API, but the official FAQ says collaboration is **not built in** because transport, persistence, identity, and authorization are host-app responsibilities. The hosted app's `excalidraw-app/collab` is a reference implementation, not a guarantee of the package. ([FAQ, v0.18.1/a2ec288, 2026-04-20](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/dev-docs/docs/@excalidraw/excalidraw/faq.mdx#L3-L5); [host props, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/dev-docs/docs/@excalidraw/excalidraw/api/props/props.mdx#L5-L33))

### 4.2 Free hosted live rooms

- **Room addressing:** a room gets a random 10-byte room ID and a separate random encryption key. The collaboration URL is `#room=<roomId>,<roomKey>`; putting the key in the fragment prevents it from being sent to the server as a normal URL component. ([app constants, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/excalidraw-app/app_constants.ts#L31-L36); [room-link source, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/excalidraw-app/data/index.ts#L128-L160))
- **Transport:** the first-party app dynamically loads `socket.io-client`, uses WebSocket first with HTTP-polling fallback, and emits persistent versus volatile events into Socket.IO rooms. ([Collab startup, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/excalidraw-app/collab/Collab.tsx#L481-L541); [official design write-up, published 2020-03-29](https://plus.excalidraw.com/blog/building-excalidraw-p2p-collaboration-feature))
- **Encryption:** scene, pointer, idle, and follow payloads are JSON/UTF-8 encoded and encrypted with a random IV before emission. The helper uses browser Web Crypto AES-GCM with the stable package's 128-bit key setting; receivers decrypt client-side. ([Portal encryption, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/excalidraw-app/collab/Portal.tsx#L84-L100); [AES-GCM helper, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/data/encryption.ts#L4-L28); [E2EE design write-up, published 2020-03-21](https://plus.excalidraw.com/blog/end-to-end-encryption))
- **Event model:** `SCENE_INIT`, `SCENE_UPDATE`, mouse/laser location, idle status, and followed-user viewport bounds are explicit message types. Remote selections are carried with pointer updates and rendered as collaborator UI on the interactive canvas. ([message types, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/excalidraw-app/data/index.ts#L76-L118); [remote cursor rendering, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/components/canvases/InteractiveCanvas.tsx#L74-L144))
- **Bandwidth behavior:** incremental broadcasts include elements whose version is newer than the last broadcast version; the app queues a full-scene resync every 20 seconds. Pointer updates are throttled to 33 ms (about 30 fps). Full resync is a recovery mechanism for dropped/diverged messages, not a CRDT operation log. ([Portal delta selection, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/excalidraw-app/collab/Portal.tsx#L141-L182); [timings, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/excalidraw-app/app_constants.ts#L2-L9); [full resync, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/excalidraw-app/collab/Collab.tsx#L911-L953))
- **Convergence:** reconciliation is the union of local and remote element IDs. A locally edited/new/resizing element is protected; otherwise the higher `version` wins, and equal versions use the lower `versionNonce` as the deterministic tie-break. Fractional indices order the merged scene. This is effectively per-element last-writer-wins reconciliation, not a general CRDT. ([element metadata, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/element/types.ts#L53-L67); [reconcile algorithm, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/data/reconcile.ts#L19-L40))
- **Persistence:** stable free-app collaboration stores encrypted scene blobs and encrypted/compressed file payloads in Firebase and reconciles transactions before update; the browser-local app pauses its normal local save during a room. This is the OSS hosted-app reference implementation, not a description of the proprietary Plus backend. ([Firebase persistence, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/excalidraw-app/data/firebase.ts#L83-L112); [transactional reconcile/save, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/excalidraw-app/data/firebase.ts#L183-L242))
- **History:** 0.18.0 introduced multiplayer-aware undo/redo. The store emits element/app-state deltas; remote updates refresh snapshots without becoming local undo entries, and history entries apply the latest remote state when popped. ([0.18.0 changelog](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/CHANGELOG.md#L20-L23); [store increment model, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/store.ts#L40-L73); [remote-aware history, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/history.ts#L180-L205))
- **Free link semantics versus Plus:** a free live-room URL grants the collaboration capability encoded in the link; official Plus features separately advertise edit/view rights, read-only links, and access management. Do not project Plus ACL behavior onto an OSS room implementation. ([pricing/feature comparison, accessed 2026-09-24](https://plus.excalidraw.com/excalidraw-plus-vs-excalidraw))

The 2020 first-party architecture article calls the live path “pseudo-P2P”: a central server relays encrypted messages but does not coordinate plaintext state. That remains useful design history, but the **current stable source also persists encrypted room state/files**, so “server stores nothing” should not be used as a current free-app architecture claim. ([design article, 2020-03-29](https://plus.excalidraw.com/blog/building-excalidraw-p2p-collaboration-feature); [current stable Firebase source, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/excalidraw-app/data/firebase.ts#L170-L242))

## 5. Rendering and performance architecture

### 5.1 Scene and canvas organization

- **Serializable scene model:** elements are JSON-serializable and explicitly designed to be shareable between peers; selection and render state are not embedded in the shared element object. The `Scene` maintains ordered all-element/non-deleted arrays plus ID maps, avoiding repeated ID lookup and avoiding allocation when a mapping changes no element. ([element contract, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/element/types.ts#L198-L213); [Scene maps/cache, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/scene/Scene.ts#L138-L172))
- **Two canvas layers:** a static canvas paints scene elements, while an interactive canvas paints selection boxes, handles, snap lines, remote cursors, and other UI. The app mounts both, and the interactive source explicitly documents that split. ([app mount, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/components/App.tsx#L1728-L1784); [interactive-scene purpose, master 1118751, 2026-09-24](https://github.com/excalidraw/excalidraw/blob/1118751f3e4958a0dc3d71934c093584fdb7c6f5/packages/excalidraw/renderer/interactiveScene.ts#L2103-L2114))
- **2D Canvas, DPR-aware:** the reviewed renderer uses `HTMLCanvasElement` and `rough.canvas`; backing dimensions are multiplied by device pixel ratio. The master version adds device-pixel snapping for cached bitmaps. ([stable element canvas generation, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/renderer/renderElement.ts#L204-L262); [master pixel snapping, commit 1118751](https://github.com/excalidraw/excalidraw/blob/1118751f3e4958a0dc3d71934c093584fdb7c6f5/packages/element/src/renderElement.ts#L730-L752))

### 5.2 Caching and scheduling

- **Rough.js shape cache:** generated Rough.js drawables are stored per element object in a `WeakMap`; export deliberately regenerates shapes to guarantee current output. ([ShapeCache, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/scene/ShapeCache.ts#L13-L85))
- **Per-element offscreen bitmap cache:** normal editor rendering creates a padded offscreen canvas per element and caches it in another `WeakMap`. Cache entries are regenerated for zoom/theme/bound-text/crop/frame-opacity changes; zoom gestures can deliberately reuse the old scale to avoid regenerating on every frame. Export bypasses this bitmap path and draws vectors. ([bitmap cache, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/renderer/renderElement.ts#L525-L580); [export path, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/renderer/renderElement.ts#L759-L789))
- **Image cache:** image `HTMLImageElement` promises/results are cached by file ID and initialized concurrently with `Promise.all`. ([image cache, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/element/image.ts#L27-L81))
- **RAF throttling and memoization:** static and interactive renders are animation-frame throttled; React-facing canvas props are shallow-compared. The first-party app explicitly sets `window.EXCALIDRAW_THROTTLE_RENDER = true`. ([React throttling, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/reactUtils.ts#L19-L60); [app flag, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/excalidraw-app/App.tsx#L132-L139); [static canvas memoization, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/components/canvases/StaticCanvas.tsx#L86-L141))
- **Font work off-thread:** SVG font subsetting uses a lazy singleton Web Worker pool and transferable buffers, with main-thread fallback. In the reviewed stable source this worker path is for glyph subsetting, not the core scene renderer. ([font subset worker, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/subset/subset-main.ts#L7-L71); [0.18.0 font-subsetting highlight](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/CHANGELOG.md#L28-L34))

### 5.3 Current scalability boundary

Viewport culling exists, but it is a full linear scan. Stable `Renderer.getRenderableElements` iterates every non-deleted element and calls `isElementInViewport`; master retains the same fundamental loop after extracting memoized visible arrays. The ID `Map` accelerates identity lookup but is **not a spatial index**. ([stable culling loop, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/scene/Renderer.ts#L23-L64); [master culling loop, commit 1118751, 2026-09-24](https://github.com/excalidraw/excalidraw/blob/1118751f3e4958a0dc3d71934c093584fdb7c6f5/packages/excalidraw/scene/Renderer.ts#L200-L239))

This is corroborated by open first-party issue **#10512**, “Renderer performance degrades due to full scene traversal on viewport updates” (opened 2025-12-14, still open on 2026-09-24), which reports O(N) work on pan/zoom/resize. A separate open issue proposes spatial indexing, but its suggested percentage gains are proposals, not measurements and should not be quoted as benchmark results. ([issue #10512](https://github.com/excalidraw/excalidraw/issues/10512); [issue #10063, opened 2025-10-04](https://github.com/excalidraw/excalidraw/issues/10063))

The defensible performance baseline is therefore: **caching and frame scheduling are mature; broad-scene viewport queries remain a known linear bottleneck.** A focused Dripl comparison, source citations, and browser-measurement plan are maintained in [`docs/excalidraw-performance-research.md`](./excalidraw-performance-research.md). No official maximum element count or universal FPS guarantee was found in the reviewed first-party material.

### 7.2 Current limitations

- The canvas itself is a drawing surface with a “Drawing canvas” fallback text node, but the stable source does not expose a DOM/accessibility representation for each canvas element. The open maintainer-collaborator accessibility discussion explicitly says screen-reader support is limited mainly to the interface, not canvas contents. ([interactive canvas source, v0.18.1/a2ec288](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/components/canvases/InteractiveCanvas.tsx#L148-L173); [issue #5759, 2022-10-13, open](https://github.com/excalidraw/excalidraw/issues/5759))
- The broad Deque-audit issue **#7492** remains open and includes findings such as missing/misleading focus indication, inability to draw basic shapes with keyboard alone, contrast problems, and missing discernible names. Its original audit targeted v0.15.2, so individual old findings may have changed; it is best used as evidence that full accessibility was not declared complete, not as a claim that every 2026 control is still broken. ([issue #7492, opened 2023-12-29, open](https://github.com/excalidraw/excalidraw/issues/7492))
- A comprehensive proposed solution—parallel DOM scene mirror, accessible element names/colors, spatial/flow navigation, keyboard creation/manipulation, image alt text, and live announcements—is still **open and unmerged** in PR #11661. A narrower keyboard-only rectangle/diamond/ellipse placement PR #12128 is also open. Therefore Excalidraw should not be described as shipping WCAG 2.2 AA non-visual canvas editing at this cutoff. ([PR #11661, 2026-07-14, open/unmerged](https://github.com/excalidraw/excalidraw/pull/11661); [PR #12128, 2026-09-19, open/unmerged](https://github.com/excalidraw/excalidraw/pull/12128))
- Open first-party issues also document current gaps in distinct color-swatch names, dialog accessible names, main-menu naming, and Windows high-contrast support. These should be checked before claiming complete WCAG conformance. ([color names #11641](https://github.com/excalidraw/excalidraw/issues/11641); [dialog naming PR #12022, open](https://github.com/excalidraw/excalidraw/pull/12022); [main-menu naming #11297](https://github.com/excalidraw/excalidraw/issues/11297); [high contrast #8088](https://github.com/excalidraw/excalidraw/issues/8088))

### 8.2 Self-hosting boundary

The official Docker image is a client image. The current official self-hosting docs explicitly state that a self-hosted instance does **not** support sharing or collaboration; those services must be supplied separately. The docs also point developers to the separate `excalidraw-room` collaboration server for local development. ([official development/self-hosting docs, stable tag](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/dev-docs/docs/introduction/development.mdx#L39-L42); [self-hosting limitation](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/dev-docs/docs/introduction/development.mdx#L89-L102))

### 8.3 Optional proprietary extension surface

Excalidraw+'s Public API/MCP and managed workspace are optional product extensions. They should be evaluated separately from the MIT React package. The official security page documents Plus SOC 2 Type I/II and says the Plus platform is protected by RBAC, encrypted backups, vulnerability management, and related controls; those are Plus service claims, not OSS editor architecture. ([Plus changelog, May 2026 Public Beta entry](https://plus.excalidraw.com/changelog); [security page, accessed 2026-09-24](https://plus.excalidraw.com/security-and-compliance); [SOC 2 post, published 2025-06-18](https://plus.excalidraw.com/blog/excalidraw-soc2))

## 9. Baseline interpretation for product comparisons

The following are conclusions from the evidence above, not additional Excalidraw claims:

1. **Reasonable free/OSS parity baseline:** infinite canvas; pan/zoom/grid; selection; basic shape, line, arrow, text, image, eraser, and hand tools; styles/opacity; grouping, alignment, ordering, locking; undo/redo; native scene/PNG/SVG export; keyboard shortcuts; and a host-controlled React API.
2. **Mature Excalidraw differentiators:** bound/labeled/elbow arrows and flowcharts; frames; libraries; scene search/command palette; Mermaid/chart paste; E2EE room collaboration; editable embedded image scenes; and a deep set of render/import/export utilities.
3. **Architecture worth treating as a performance baseline:** layered static/interactive canvases, DPR scaling, per-element Rough.js/bitmap caches, image caching, RAF throttling, and vector export.
4. **Architecture not safe to copy blindly:** O(N) viewport culling with no general spatial index. For large-canvas work, an R-tree/quadtree or equivalent candidate index is the obvious architectural gap identified by current source and open first-party issues.
5. **Accessibility positioning:** Excalidraw is a strong keyboard-operated editor reference, but it is not a safe benchmark for complete screen-reader/non-visual canvas support until the currently open accessibility work is merged and verified.
6. **Scope discipline:** keep Free/OSS, current hosted additions, Excalidraw+, Public API/MCP beta, and forthcoming Enterprise capabilities in separate comparison columns.
